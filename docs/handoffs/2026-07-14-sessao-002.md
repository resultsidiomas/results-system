## 3. API do console de teste do agente

`backend/src/testing/test-chat.routes.ts` — testa o agente comercial via
HTTP direto, sem passar pelo WhatsApp real. Autenticado por
`TEST_CONSOLE_TOKEN` (já configurado no `.env` real).

```
GET    /api/v1/test-chat/:sessionId/messages
POST   /api/v1/test-chat/:sessionId/messages   { message }
DELETE /api/v1/test-chat/:sessionId             (reset total — apaga histórico Redis + contato de teste inteiro)
```

Testado ponta a ponta localmente (auth 401, criação de contato/conversa
isolada `test-{sessionId}` no Supabase real). Parte que depende de Redis
(histórico, reset de memória) só valida rodando na VPS — mesma limitação já
conhecida (Redis não resolve de máquina local, sem Docker).

**Frontend é escopo do Codex** — prompt de handoff com contrato completo de
API + requisitos funcionais está no scratchpad da sessão (arquivo local
temporário, não versionado). Se perdido, o contrato de API acima + os
requisitos (botão "reiniciar teste", indicador de leadScore, badge de
handoff, sessionId em localStorage) bastam pra regerar o prompt.
